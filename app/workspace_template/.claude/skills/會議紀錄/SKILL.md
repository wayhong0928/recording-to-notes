# 會議紀錄

使用者不一定懂程式。跟使用者講話一律用白話，不貼指令、不貼 JSON、不講技術名詞。

所有指令都用下面這個程式跑，路徑要加引號，每個指令都加 `--json`，讀 JSON 的結果：

```
"{{MINUTES}}" <指令> --json
```

同資料夾有兩份檔案，寫會議紀錄前要讀：`整理規則.md`（怎麼寫）、`問答式.md`（格式）。

## 1. 檢查環境

跑 `check --quick`。`ok` 是 false 時，用白話說明哪裡有問題、怎麼修，然後停下來，不要往下做。

## 2. 確認是哪幾段錄音

跑 `scan`。

- 沒有錄音：請使用者把錄音檔放進工作區的「錄音放這裡」資料夾，然後停下來。
- `unreadable` 有東西：告訴使用者哪幾個檔讀不到。
- 用表格給使用者看每一組：日期、每段的開始時間、長度、和上一段隔多久。`time_certain` 是 false 的標「時間不確定」。
- 有好幾組時，預設選 `default` 是 true 的那一組（最新的），請使用者確認。
- 組裡有 `flags` 含 `long_gap` 的段落（和上一段隔 1 小時以上）：問一句「這幾段是同一場會議嗎？」。不是同一場的話，只拿使用者指定的那幾段。
- 有 `overlap` 的段落：告訴使用者這兩段的時間重疊，問要不要都放。

接著一次問完：
1. 會議名稱。
2. 有沒有與會者名單或專有名詞要提供（可以直接打在對話裡）。
3. 有沒有自己開會時記的筆記或初稿（可以貼進來，或給檔案位置）。
4. 會議紀錄要存在哪裡。沒有特別說就存在工作區的「會議」資料夾。

## 3. 建會議資料夾

跑 `new "<會議名稱>" --date <YYYY-MM-DD> <錄音完整路徑…>`。日期用這組錄音的日期。使用者指定了存放位置就加 `--to "<位置>"`；位置在 OneDrive、iCloud 這類會同步到雲端的資料夾裡時，先提醒「錄音也會跟著上傳到雲端」，使用者同意再做。

建好之後，在回傳的 `folder` 裡：
- 有名單或術語：寫成 `0_名單與術語.txt`，一行一個。
- 有筆記：寫成 `0_我的筆記.md`，照使用者給的內容原樣存，不要改寫。

## 4. 轉逐字稿

在背景跑 `transcribe "<folder>"`（Bash 工具的 run_in_background）。告訴使用者大概要多久：第 1 步 `check` 的轉錄裝置是顯卡時，錄音總長度乘 0.1；是 CPU 時乘 0.6，沒有獨立顯示卡的一般筆電可能乘 1 以上。也告訴使用者會跳出一個進度視窗，轉完會自己關掉，中途關掉也不會停止轉錄。並說可以先去做別的事，轉好會通知。

轉錄途中：
- 使用者問進度：跑 `progress "<folder>"`，用白話回報第幾段、百分比、大概還要多久（`eta` 是秒數，null 就說還在估算）。`stale` 是 true 時說轉錄好像停了，等轉錄的結果再看原因。
- 使用者說進度視窗關掉了、想再看：跑 `progress "<folder>" --window`。

轉完讀結果：
- `ok` 是 false：用白話轉述 `error`。做完的段落已經存起來，修好後重跑會接著做。
- `prompt_dropped` 有東西：告訴使用者名單和術語太長，哪幾行沒用上。
- `fallback` 有東西：告訴使用者這次改用 CPU 轉，以及原因。

## 5. 寫會議紀錄

讀 `1_逐字稿.md`、`整理規則.md`、`問答式.md`，有 `0_我的筆記.md` 也一起讀，在會議資料夾寫出 `2_會議紀錄.md`。

- 格式完全照 `問答式.md`：開頭六個欄位、三個段落，回覆、結論的行前面空三格。
- 會議名稱填使用者講的名稱，其他欄位留空。
- 第一次寫完、還沒做任何修改（包括第 6 步的核對）之前，立刻複製一份到 `_暫存/2_會議紀錄_AI原稿.md`。這份之後永遠不改，用來比對使用者改了什麼；已經存在就不要覆蓋。

## 6. 自己核對

照 `整理規則.md`「寫完自己核對」逐條對照逐字稿檢查，有錯就改 `2_會議紀錄.md`。也確認裡面沒有逐字稿的時間戳（像 14:32:10 這種）、沒有「待確認」「發言者不明」這類註記、沒有另外列的「補充：」行，有就改掉。

## 7. 產生 Word

跑 `render "<folder>"`。Word 會自動打開。回報：
- 幾個議題、幾項決議、幾題問答（JSON 的 `counts`），刪了或合併了哪幾題。
- 聽不清楚、看不出是誰說的、筆記和逐字稿對不上的地方，逐條列出來（附逐字稿時間），請使用者確認。這些不寫進會議紀錄。
- 錄音已經搬到哪個資料夾。
- `opened` 是 false：轉述 `open_note`，告訴使用者 Word 檔的位置。
- 最後說一句：要改哪裡直接在這裡說，或把 Word 裡改過的段落貼過來。

## 8. 使用者要修改

1. 改任何東西之前，先跑 `word-status "<folder>"`。`edited` 是 true 時，**先停下來問**，等使用者回答才往下做：「你在 Word 裡改過上一版（檔名），要先把改的地方貼給我嗎？不貼的話，新版不會有那些修改。」使用者已經講了要改什麼也一樣要先問，因為 Word 裡的修改你看不到，直接產生新版會讓那些修改不見。同一版 Word 只問一次。
2. 依使用者的話（或貼來的段落）改 `2_會議紀錄.md`。`_暫存` 裡的 AI 原稿不要動。
3. 跑 `render "<folder>"` 產生新版。舊版 Word 會留著。JSON 的 `previous_edited` 是 true 而使用者沒有貼修改過來時，回報裡要再講一次：上一版 Word 的修改沒有放進新版，舊檔還在。

## 不要做的事

- 不要刪任何錄音、逐字稿或舊版 Word。
- 不要自己決定把不同天、或隔很久的錄音當成同一場，要問使用者。
- 不要把逐字稿裡沒有的內容寫進會議紀錄。
